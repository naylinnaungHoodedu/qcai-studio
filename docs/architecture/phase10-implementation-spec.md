## 1. Conflicts between plan text, paper and the fixed decisions, with resolutions

Each resolution is a refinement. None reverses a fixed decision.

1. **Item states (E2 vs paper).** E2 says "draft/candidate/frozen/retired"; the paper says "Draft, Candidate, Review, Frozen and Release". **Resolution:** six states, `draft, candidate, review, frozen, release, retired`. An item leaves `review` for `frozen` only with `validation.human_reviewed` true; frozen and release content is immutable.
2. **Where the AC tests live.** **Resolution:** `apps/api/tests/test_phase10_acceptance.py`, as in Phases 2-9; the feature unit modules live in `evaluation/tests/` (E14).
3. **Plan 6.5 "strict validate_lqs; freeze hash" vs R-25.** **Resolution:** the strict freeze check runs only in the research plane (`scripts/validate_ulqs.py --freeze`, which refuses synthetic items), where it records the dataset sha256. Public CI keeps `validate_lqs.py --allow-draft` and adds `validate_ulqs.py` on the synthetic set (plan 6.1: "public CI checks schemas on non-licensed stubs only").
4. **"EV-ids resolved to span records [Evidence E-96]" vs Phase 2 ("No API path to the private plane").** **Resolution (E3):** EV-ids resolve through a private evidence catalog to records shaped like span records (document, volume, page, offsets, byte length, content sha256 under the Phase 2 rule); public `span-<hex64>` ids resolve through the Phase 2 `SpanResolver`; `corpus_spans` never holds a private span.
5. **Plan E "no production component".** **Resolution:** the harness code is public but runs only on synthetic inputs in CI; nothing of it is in the image (M11).
6. **Strata targets (E4).** The paper gives S1-S7 = 40/25/20/15/15/20/25; the card gives A44 B28 C20 D14 E14 F12 G28. **Resolution:** the paper's targets, mapped S1-S7 → A-G by the paper's note, are PD-63, in the one data file `lqs/ulqs-v1.0-freeze-rules.json`, which records the card's allocation as the conflicting source. The choice is the PI's (DI-136). The comparison at freeze is exact; adjusting the allocation to corpus capacity is a data edit.
7. **S4's correct behaviour.** "Correct the premise or abstain". **Resolution:** a D item's `expected_behavior` ∈ {abstain, answer}, where `answer` is a premise correction with evidence and claims.
8. **Second raters.** Plan task 2: "second raters on >= 25%". **Resolution (PD-64):** at least 1/4 of non-retired items are second-rated overall, and at least ⌈n_s/4⌉ in each stratum. A second-rated item is one whose every rated unit (3.5) has at least two main-round labels.
9. **Agreement statistic.** **Resolution:** Krippendorff's α (nominal, over the labels of the live items' rated units) ≥ 0.667, compared literally as `Fraction("0.667")`, so α = 2/3 fails. Cohen's κ is reported when exactly two raters label the same units. The rubric's step 5 states this.
10. **LEX and the gate.** **Resolution:** LEX keeps the gate and differs from GATE only in `retrieval`; "its floor" is the gate's floor on the lexical path.
11. **NR differs in two variables.** NR declares `retrieval: none` and `abstention_gate: false`; AC-10-2 holds because both are declared ablation variables. NR sends and logs no evidence.
12. **Replicates.** **Resolution:** the paper's values are provisional configuration in `evaluation/config/harness_parameters_v1.json` (PD-68): a default of 1 and a subsample of stratum A, 40 items, 3 replicates, in sha256 order. A spec that omits `replicates` takes them, and the record pins the file's sha256 and which values it supplied. A live or confirmatory spec must keep a subsample with at least 2 replicates (`replicate_subsample_required`, exit 2), so its record always reports replicate variance. The synthetic spec uses 2 A items × 3 replicates. Metrics use replicate 1; the replicates feed `replicate_variance`.
13. **Retries.** **Resolution:** 3 retries (4 attempts), the same file's default; a spec may set 0-10. A failure after them is an outcome, `provider_failure` with its reason, counted in the SLIs.
14. **The scanner's location (task 7) vs E10's public CI.** **Resolution:** CI runs the same scanner on fingerprints built in memory from a committed synthetic fixture with a published salt. Real fingerprints are DI-141.
15. **Short ULQS texts.** A 12-word shingle cannot match short questions. **Resolution:** a ULQS fingerprint family `qcai-ulqs-fingerprints/1`: a salted HMAC of every normalized whole text field of at least 3 words plus 6-word shingles (PD-71). The scanner applies the exact family to every line, sentence and decoded JSON string.
16. **The fingerprint file holds its salt.** **Resolution:** a real fingerprint file is research-plane material, and the builder refuses a public path. Only the synthetic fixture's salt is public.

## 3. Data shapes

- All JSON is UTF-8. Script records use `canonical.dumps_record` (`json.dumps(value, indent=1, sort_keys=True, ensure_ascii=False) + "\n"`, written LF); JSONL lines use `canonical.dumps_line` (sorted keys, compact separators).
- JSON values are hashed with `canonical.canonical_sha256`, which matches `app.core.config_package.canonical_sha256`. Text files are hashed with `canonical.lf_sha256`.

### 3.1 ULQS v1.0 record (`lqs/ulqs-v1.0.schema.json`, `$id` `ulqs-item-schema-1.1`)

| Field | Rule |
|---|---|
| `item_id` | `^(ULQS\|SYN)-([A-G])-([0-9]{3,})$`. The letter equals `stratum`. `SYN-` ⇔ `license_class == "synthetic"`. |
| `schema_version` | `"1.0"` (rc1 input) or `"1.1"` (v1.0 records) |
| `dataset_version` | `"ULQS-v1.0"`, required when `schema_version` is 1.1 |
| `corpus_version` | `^QCAI-CORPUS-[0-9]{4}-[0-9]{2}-[0-9]{2}$` or `SYNTHETIC-CORPUS-v1`. Never part of an id (R-19). |
| `status` | `draft \| candidate \| review \| frozen \| release \| retired` |
| `stratum` | `A`..`G` (S1..S7) |
| `corpus_scope` | non-empty unique list of the schema's four scope values (the three corpus volumes and `synthetic`) |
| `topic`, `concepts` | a non-empty string; a non-empty list of non-empty strings |
| `difficulty` | `easy \| medium \| hard` |
| `bloom` | `remember \| understand \| apply \| analyze \| evaluate \| create` |
| `retrieval_type` | `single_span \| multi_span \| negative_evidence \| multi_turn` |
| `question`, `weight`, `leakage_risk` | a non-empty string; a number > 0; `low \| medium \| high` |
| `license_class` | `private_eval_full_span \| synthetic` |
| `quality_scores` | exactly the five keys, integers 0..3 |
| `provenance` | `created_utc`, `author` (a role code in records the migrator writes; PD-61), optional `migrated_from`, `migration_disposition` ∈ {convert, revise}, `note` |
| `validation` | `citation_resolved`, `evidence_verified`, `duplicate_checked`, `human_reviewed` (booleans; `human_reviewed` optional, default false) |
| `item_kind` | `instructional \| bibliographic \| null` |
| `split` | `calibration \| confirmation \| null` |
| `expected_behavior` | `answer \| abstain`. Required for A-E; absent for F and G. |
| `evidence_ids` | a unique list of `^EV-(2025\|2026\|IND\|SYN)-p[0-9]{3}-[0-9]{2}$` or `^span-[0-9a-f]{64}$`; `EV-SYN` only on synthetic items |
| `atomic_claims` | `[{claim_id, text, evidence_ids}]`; `claim_id` is `<owner id>-c<n>` (item or turn), unique in the dataset; `evidence_ids` non-empty and ⊆ the owner's |
| `gold_answer`, `abstention_rationale`, `reasoning_chain`, `notes` | a string or a string list |
| `negative_evidence` | `{corpus_version, sections_searched[str], queries[str], methods ⊆ {lexical_bm25, regex, semantic}, verdict: none_found, verified_utc, limitations}` |
| `base_question`, `replays`, `invariance_checked` | G only; `replays` holds three entries with the levels beginner, intermediate and advanced, each once |
| `conversation` | F only; at least 2 turns `{turn_id <item_id>-t<n>, user_utterance, resolved_query, expected_behavior, gold_answer?, evidence_ids?, atomic_claims?, abstention_rationale?, negative_evidence?}` |

Conditional rules: **A** answer, at least 1 evidence id, at least 1 claim and a gold answer; **B** as A with at least 2 evidence ids; **C, E** abstain, with `negative_evidence` and `abstention_rationale`, and no `evidence_ids`, `atomic_claims` or `gold_answer`; **D** as C, or answer (a premise correction) as A; **F** every turn valid by its own `expected_behavior`, no item-level evidence, claims or gold answer; **G** `base_question`, 3 replays, at least 1 evidence id and at least 1 claim. ### 3.4 Evidence catalog (research plane; JSONL)

Each line is `{"evidence_id", "document_id", "volume" (one of the three corpus volumes or synthetic), "page" (int ≥ 1), "char_start", "char_end" (0 ≤ start < end), "byte_length" (int ≥ 1), "content_sha256" (hex64), "corpus_version", "text"?}`. ### 3.11 Payload log, run events, access log

- **`payload_log.jsonl`** (`payload-log-v1`): one line per request, in plan order, with exactly `log, purpose, run_id, request_key, arm, item_id, unit, replicate, seed_hex, prompt_version, prompt_sha256, prompt_bytes, evidence [{pointer, content_sha256, bytes}], response_sha256, response_bytes, outcome, failure_reason, attempts, model_id, cost_units, role, cell` (`role` `answer`, `verify`, `two-pass-evidential`, `two-pass` or `single-pass`; `cell` the E2 verifier or E4 model id, else null). Every string matches an id, hex, enumeration or null pattern, and sizes are integers; there is no free-text field. `evidence` is empty for an arm whose retrieval is `none`. In stub and recorded modes `prompt_sha256` and `prompt_bytes` come from the canonical envelope `{prompt_version, item_id, unit, arm, evidence}` (a design request's adds `role`, `cell` and `subject`, and an E3 `two-pass` request's adds `locked`, the evidential response's sorted `[claim_id, cited]` pairs it was sent). `failure_reason` is one of `timeout`, `rate_limited`, `server_error`, `refused_payload`, `recorded_missing`, `evidential_pass_failed` or null.
- **`run_events.jsonl`** (`start|interrupted|resumed|completed`, with `run_id`, `purpose`, `completed_requests`, `planned_requests`, `reason`?, `commit`?; `start` and `resumed` also carry `run_digest`; the `start` event of a confirmatory or live run also carries `started_on`, the UTC day the run was planned): scanned, not byte-compared.
- **Access log** (`access-log-v1`; `docs/evaluation/phase10/access-log-format.md`): roles, actions, artifact kinds and sha256 only; required whenever inputs are not all synthetic, with the actor's role (`--actor-role`). Kinds: `ulqs_items`, `evidence_catalog`, `corpus_text`, `ratings`, `licensed_text`, `fingerprints`, `agreement_record`, `freeze_record`, `scan_report`, `scan_target`, `run_spec`, `recording`, `run_output`, `irb_record`, `osf_record`, `governance_record`, `agent_check_record`, `verification_set`, `e4_responses`. A `run` line carries an `outcome` (`started`, `completed`, `interrupted`, `refused`); no other line does. The runner logs the spec read, each input when the planner reads it (the items, the catalog, the recording, an E2-E4 design's pinned inputs `verification_set`, `e4_responses` and `ratings`, and each governance record with the sha256 of the bytes read, matching its pin or not), each checkpoint file it reads (`run_output`, the sha256 of the bytes: `run_events.jsonl` when a dated resume is planned, and `run_events.jsonl` and `responses.jsonl` when `execute_run` starts, before any checkpoint check), the start and the outcome, so a refused run keeps its reads; the validator its inputs (items, the previous set, the agent-check record, the catalog, the corpus text read, the ratings) and its records; the migrator the rc1 items and the v1.0 items it writes; the fingerprint builder each licensed text and the items it reads and each fingerprint file it writes; the research-log scanner, whenever it reads research fingerprints (`--fingerprints`, which then requires `--access-log` and `--actor-role`), each fingerprint file (`fingerprints`, with the digest the builder logged), each `--path` target (`scan_target`) and `--research-logs` directory (`run_output`, a digest of the files it read) and the report it writes (`scan_report`). Every script logs an input as soon as it is read, before any check that can refuse it, so a refused validation, migration, build or scan still leaves its reads.

### 3.13 Governance records (research plane)

- **IRB** (`irb-approval-v1`): `protocol_number` ^[A-Za-z0-9-]{3,40}$, `determination` ∈ {approved, exempt}, `approval_date`, `expiry_date` (YYYY-MM-DD or null, not before approval), `letter_sha256`.
- **OSF** (`osf-registration-v1`): `doi` ^10\.17605/OSF\.IO/[A-Z0-9]{5,}$, `registered_date`, `analysis_plan_sha256`.
- **Freeze record** (`ulqs-freeze-record-v1`, `validate_ulqs.py --freeze-out`; exactly `governance.FREEZE_RECORD_KEYS` plus `record`): `dataset_sha256`, `dataset_content_sha256`, `rules_sha256`, `agreement_sha256`, `agent_check_sha256` (the canonical sha256 of the agent-check record), `agent_report_sha256` (the agent's full-report sha256, the record's `report_sha256`), `agent_model_id`, `agent_detected_defects`, `agent_false_alarms`, `agent_missed_defects`, `disagreements_adjudicated`, `items_changed_after_flag`, `items_changed_without_flag`, `passed`, `failures`.
- **Agent re-check** (`ulqs-agent-check-v1`, `validate_ulqs.py --agent-check`; conflict 35): `checked_items` (the id of each item live when the agent checked, that is, every item live in the set the freeze starts from and every item live now, mapped to its status-free content sha256 as the agent checked it, `ulqs.item_content_sha256`; an item retired since stays in it and counts as changed), `agent_model_id`, `model_chosen_before_check` (true), `verdict_schema` "v2", `report_sha256` (the agent's full report, kept in the research plane), `items_checked`, `disagreements`, `disagreements_adjudicated`, `adjudicated_by_non_reviewer` (true: the adjudicating claim rater did not review the item), `agent_detected_defects`, `agent_false_alarms`, `agent_missed_defects` (non-negative integers), `items_changed_after_flag` (the ids of the changed items changed after one of the agent's flags, at most as many as it flagged, so the agent's E2 accuracy can be reported with and without them) and `items_changed_without_flag` (the ids of the changed items changed for another reason, such as an item retired to trim a stratum to its target); together the two lists name exactly the changed items, each once. The validator refuses a record that does not have this shape when it reads it (exit 2, `ulqs.agent_check_shape_ok`). No name, label or item text.
- **Plan H records** (live runs): `provider-terms-v1` (`provider_id`, `recorded_date`, `retention_recorded`, `training_recorded` and `publication_recorded`, each `true`, and `terms_sha256`); `licence-ruling-v1` (`determination` ∈ {permits, negative}, `ruling_date`, `letter_sha256`); `research-use-confirmation-v1` (`confirmation` "confirmed", `confirmed_date`, `letter_sha256`). The spec references each by `{"path", "sha256"}`; `provider_terms` may be a list, one record per provider the live run names in `responder.live.providers`, and no record may be dated after the run window's start.
- **Pre-run scan:** a scan report (3.14) referenced by `{"path", "sha256"}`, checked by `governance.scan_refusals` (conflict 32).
- **The run window** (`governance` module docstring; confirmatory and live runs). Every record date is judged against two days the runner supplies, never against the spec's `created_at`: `today`, the current UTC date when the run is planned (`governance.utc_today`, read once), and `start`, the day the run's data began to flow, the earliest of today, the `started_on` of the output's start event (`--resume`; `runner.checkpoint_start_refusals`) and the `started_on` a live recording's header states (a confirmatory recorded replay; `governance.recording_start_refusals`). The IRB must be approved on or before `start` (`irb_not_yet_approved`) and not expired on `today` (`irb_expired`); the OSF registration (`osf_registered_after_run`) and every plan H record (`provider_terms_after_run`, `licence_ruling_after_run`, `research_use_after_run`) must be dated on or before `start`; `created_at` must not be after `today` (`created_at_in_future`). A resumed checkpoint whose first event is not a `start` with an ISO `started_on` not after today is refused (`run_start_invalid`), and one with another run's digest (`checkpoint_mismatch`); a live recording without an ISO `started_on` (`recording_started_on_missing`) or with one after today (`recording_after_run`) is refused. `execute_run` runs a dated plan only into the output it was judged on: a plan judged as a fresh start into an output with no run events, a resume into the checkpoint whose `started_on` it read (`checkpoint_mismatch`, exit 2). A fresh start's event records the planning day as `started_on`. An earlier `start` only adds refusals, so a start event or recording header written by hand gains nothing over a fresh start today, and a resume or replay on any later day is judged on that day. The checkpoint, the header and the records' dates are the operator's: these are consistency checks, not proof or tamper evidence (an externally timestamped start is DI-143).

### 4.7 `statistics.py` (`wilson_interval` and `mcnemar_exact` unchanged; additions)

`holm` (sorted by (p, name); adjusted_i = min(1, max_{j ≤ i} (m − j + 1)·p_(j)); reject when adjusted ≤ α), `wilson_upper_bound`, `sample_variance` (`sample-variance-v1`), `least_squares_slope`, `hash_resample_indices` (`hash-resample-v1`: first 8 bytes of `sha256(f"{seed}\x1f{resample}\x1f{j}")` mod n), `bootstrap` (two-sided percentile; bounds at the sorted replicates ⌊(1−level)/2 · B⌋ and ⌈(1+level)/2 · B⌉ − 1). The analysis plans' registered tests, listed in `REGISTERED_TESTS` (the only names a plan may mark implemented): `bootstrap_one_sided` and `cluster_bootstrap_lower_bound` (lower bound at the sorted replicate ⌊α · B⌋; `reject` when it exceeds `margin`; `p_value`, the share of replicates at or below the margin, so that `reject` holds exactly when `p_value` ≤ α), `paired_bootstrap_one_sided` (mean(left) − mean(right) over pairs resampled whole; H1c's margin −0.05), `paired_bootstrap_auc_one_sided` (H2c: AUC(left) − AUC(right) over items resampled whole with both scores, `auc` the Mann-Whitney area with ties at one half; a replicate with one class only counts at or below the margin), `cluster_bootstrap_bca_one_sided` (Efron's BCa: z0 = Φ⁻¹(share of replicates below the estimate), acceleration a = Σd³ / (6 (Σd²)^1.5) from the leave-one-cluster-out jackknife, bound at the replicate ⌊Φ(z0 + (z0 + z_α)/(1 − a(z0 + z_α))) · B⌋; undefined when no replicate, or every one, lies below the estimate; its `p_value` is the BCa one, Φ(w/(1 + a w) − z0) with w = Φ⁻¹(q) − z0 and q the share at or below the margin, 0 or 1 at the ends, so that `reject` holds exactly when `p_value` ≤ α, while `share_at_or_below_margin` stays the plain share), `two_level_bootstrap_share_le_zero` (`hash-resample-two-level-v1`: groups resampled with `seed`, then each chosen group's members with seed `f"{seed}\x1f{b}\x1f{k}"` and resample 0; the share of replicates ≤ 0, also its `p_value`, H4a's Holm input, and `interval_95`, the 95% percentile interval of the replicates at the sorted replicates ⌊0.025 B⌋ and ⌈0.975 B⌉ − 1, MR-1's interval of the difference), `friedman` (n ≥ 2 blocks of k ≥ 3 treatments, average ranks, tie correction 1 − Σ(t³ − t)/(n k (k² − 1)), χ² with k − 1 df) and `paired_tost` (p = max of the two one-sided paired t-tests at ± margin, n − 1 df; equivalent when p ≤ α). The tails come from `normal_cdf` (erf), `normal_quantile` (bisection), `chi2_sf` (regularized incomplete gamma) and `student_t_cdf` (regularized incomplete beta). None has run on research data (DI-138).

check every reused line against its request (`verify_responses`); a request with `depends_on` (an E3 `two-pass` request) is sent with the locked claims of the response it depends on (`with_dependency`, `locked_claims`), or, when that response failed, not sent and recorded as `provider_failure` with `evidential_pass_failed`; up to 1 + `retries` attempts per request, then `provider_failure`; `ProviderOutage` appends an `interrupted` event and raises `RunInterrupted` (exit 5); each response line is appended and fsynced; at the end the payload log (validated), the run record and a `completed` event are written; a write into the output that fails (the output directory is a file or lies under one, an output file is a directory or cannot be opened for writing, a full disk), the truncation of a partial checkpoint line on resume and the close of the responses file included, refuses the run (`output_unwritable`, exit 2, `_writing`); a `dated` plan's `start` event carries `started_on` (its `planned_on`). The record and the payload log depend only on (plan, responses).
- **`compute_metrics`** (per arm, replicate 1): any null label → `{"status": "awaiting_labels"}`; `ER` (eq. 12; provider failures excluded and counted); `CF`; `CP` and `CR` (claim-level proxies, labelled); `fabrication`; `citation_existence`; `CA` and `AR` (through `correct_abstention`); `abstention_decay` (by turn depth, with a slope); `IV` over the G items whose three levels completed (others excluded and counted).
- **Comparisons:** GATE vs each other arm, `mcnemar_exact` on paired unit errors, then `holm`; synthetic runs are labelled "synthetic: no arm effect by construction (R-f)", others "exploratory comparison; not a pre-registered test". **Registered tests** (an E1 run; E2-E4 in 4.14; conflict 37): H1a and H1b `mcnemar_exact` paired by item on answerable items (`experiments.answerable_item_errors`: an item's error is 1 when a response to one of its answerable units, gold `answer`, replicate 1, provider failures excluded, holds a Fabricated or Attribution-error claim, an abstention scoring 0; gold-abstain units do not enter; VBT RevB Table I), H1c `paired_bootstrap_one_sided` of the per-item answer rate (the share of answerable units answered, replicate 1) VLOOP − GATE with the plan's margin, seed `hashed_hex(run_id, "registered", "H1c")`, then `holm` over the three p-values. **Bootstrap:** the VLOOP − GATE item-level error difference, items as clusters, percentile, seed `hashed_hex(run_id, "bootstrap", "VLOOP-GATE-ER")`. **Replicate variance:** per arm, the ER of each replicate over the subsample (from the pinned, effective `replicates`), then `sample_variance`.

### 4.14 `experiments.py` (the E2, E3 and E4 designs; PD-75)

The spec's `design` block names everything D-07 has not pinned; the provisional defaults are `harness_parameters_v1.json`'s `designs` block (PD-75), and the record pins the effective design (`pins.design`). Each design's requests run through the responder seam (the stub: `experiments.stub_verdict` for a verification, `experiments.stub_generation` for an E3 pass, whose `two-pass` presentation pass answers with the locked claims it is sent, `stub_response` otherwise; `providers.stub_for`). Replicates: E2 replicates the claims of the subsample's items and E4 the subsample's units, as E1 does; E3 uses no subsample, its replicate variance being its single-pass repeats. Every value the planner or the computation reads is shape-checked first (`shape_refusals`, exit 2, the field named). The registered protocol is `experiments.REGISTERED_DESIGN` (E3 `repeats` 3; E4 `streams` 1000, `stream_length` 2000, `shift.at` 1000, `shift.points` 0.10; VBT RevB Sec. VIII-D) and each hypothesis's registered `resamples` (H2a, H2b 10,000): a live run or a run over non-synthetic data must run it (`design_departs_from_registration:<field>`, exit 2), and a synthetic run that departs pins each departure (`pins.design.departures`, `{field, registered, effective}`) and its family reads `protocol: departs_from_registration`, else `registered`. A design request's key adds its `role`, `cell` and `subject` to E1's composition (`design_request_key`), and its seed is `hashed_hex(run_id, arm, item_id, replicate, role, cell, subject or unit)[:16]` (`design_seed`). Every family's tests enter Holm through their p-value; an undefined statistic is reported as `{"status": "undefined"}`, an input not yet collected as `{"status": "awaiting_ratings"}`, a hypothesis whose responses still lack the human labels it reads as `{"status": "awaiting_labels"}`, and a non-finite number as null; the family lists its waiting hypotheses (`pending`), whose p-values Holm has not yet seen.

- **E2** (`design`: `verification_set` {path, sha256, `generator_family`}, optional `e4_responses` {path, sha256}, `verifiers` [{`model_id`, `family`}], optional `ratings`, `resamples`, `dawid_skene_iterations` (a positive integer)). The verification set is every labelled claim of the pinned E1 responses (replicate 1, answered; a line outside the run's live items is refused, `verification_set_items`, and a line that is not a response line with an integer replicate, string or null unit and cell, and a list of claims each with a string `claim_id`, a string or null `label` and a list of string `cited`, `verification_set_invalid`, both exit 3; no labelled claim at all is `verification_set_empty`, exit 2) and, when given, of E4 responses, whose generator is each line's model (`cell`) with the family the verifier list gives. Each verifier verifies every claim generated outside its own family (`verify`, `cell` the verifier, evidence the claim's resolving citations); the panel is the three verifiers outside the E1 generator's family, of three families (`e2_panel_invalid`, exit 2). Metrics: each verifier's and each panel rule's (1oo3, 2oo3, 3oo3, a two-coin Dawid-Skene posterior above 0.5 after `dawid_skene_iterations` EM steps) precision, recall and F1 against the gold error labels (Fabricated, Attribution error), on the claims all three members verified; the members' miss rates on erroneous claims, each rule's observed and independence-predicted miss rate (eqs. 1-2) and DR (eq. 3). H2a `cluster_bootstrap_bca_one_sided` over items of F1(2oo3) - max_j F1(j); H2b `cluster_bootstrap_lower_bound` over items of DR against 1 (a resample with no erroneous claim or a member that never misses counts at or below the margin; an undefined estimate is `undefined`); H2c `paired_bootstrap_auc_one_sided` of the panel's score (the largest share of members objecting to one of a response's claims) against the novices' (minus the mean trust rating) from a pinned `novice-trust` ratings file, else `awaiting_ratings` (Group B, after IRB). Resamples: the hypothesis's (H2a, H2b 10,000), or `design.resamples` when set (a departure for H2a and H2b; H2c registers none). Replicate variance: each verifier's objection rate per replicate.
- **E3** (`design`: optional `arm` (one of the seven arms), `fixed_level`, `repeats`, `h3b_feature` (one of `fk_grade`, `guiding_questions`, `prerequisite_recaps`, `length`)). - **E4** (`design`: `models` [{`model_id`, `family`, `price_per_input_unit`, `price_per_output_unit` (positive decimals), `local`, optional `later_price` {`from`, `price_per_input_unit`, `price_per_output_unit`}}] (four, one local), `pilot_commercial` (a commercial model), `shift` {`model`, `topic`, optional `at`, `points`}, optional `streams`, `stream_length`, `epsilon` (a rational in [0, 1]), `linucb_alpha` (a rational ≥ 0), `local_cost` {`energy`, `amortized_hardware`} (non-negative USD decimals), `ratings`). VIII-D: "time to first token and total time (median and 95th percentile)") from the `latency` its responses record (median, and the nearest-rank 95th percentile; `not_recorded` when none does). The replay population is every unit with a completed GATE and VLOOP response from all four models: y = 1 when the GATE response is clean, the delivered quality the VLOOP response's (eq. 8 over its `signals` with the pinned package's weights, else 1 for a clean answer to an answerable unit), the cost the VLOOP response's. H4a `two_level_bootstrap_share_le_zero` with `indexed`: per replicate the items are resampled (and their units), then one stream of `stream_length` requests is drawn, the shift applied from request `at` (each clean outcome of `shift.model` in `shift.topic` replaced, at the rate points / (1 - base error), by one of its own failed outcomes in that topic), and eight policies are replayed: the Phase 9 controller (`app.services.ranking` over the pinned package's ranking block: a request goes to Algorithm 1's choice and its outcome is applied as an input; a fallback abstains) with and without hysteresis (promotion delta 0, n_d 1), static-best (the best quality per price over the resampled pool), round-robin, cheapest-eligible (the lowest cost over the pool), epsilon-greedy (each model once in adapter-id order, then the best mean reward unless a seeded draw below epsilon explores) and a LinUCB-style bandit on the topic (the largest mean reward over 1 + pulls plus alpha √(1 / (1 + pulls)), ties by adapter id; reward: quality per price), and threshold escalation (cheapest over the pool first, paying every failed first pass). The statistic is the controller's quality per price minus the larger of static-best's and round-robin's, and the share of streams at or below 0 is the p-value. The record adds the 95% percentile interval of that difference over the streams (`difference_interval_95`, MR-1's "95% interval of the difference"), each policy's mean and 95% percentile interval, and the controller's figures under MR-2's and MR-3's counting rules, labelled as figures and not the criteria's outcomes (both stay `criteria_only`, DI-138): the detection delay (the degraded model's responses in the shifted topic from the shift to the first alarm on that model's CUSUM stream for the topic's context, `model-cluster:<model>:<cluster>`), the false alarms (every alarm before the shift), and the incumbent switches per context per 1,000 drift-free requests (the requests before the shift). A model with a `later_price` gets the replay again at the later prices beside it, not entering Holm; the base prices must be in force at the run's start (`e4_later_price_in_force`), and the later replay is reported whenever a later price is given, since the record carries no wall clock to tell whether the run straddled its date (conflict 40). H4a waits for labels (`awaiting_labels`) until every model's GATE and VLOOP responses are labelled (replicate 1). H4b `mcnemar_exact` of the local model's and `pilot_commercial`'s GATE item-level errors on answerable items, paired by item, and the `paired_tost` of their VLOOP responses' expert EQC ratings from a pinned `eqc` ratings file (else `awaiting_ratings`), reported `inconclusive` and not entering Holm while ICC(2,k) and Cronbach's alpha are not implemented (DI-138); H4b waits for labels only until the GATE responses of the local and the pilot-selected commercial model are labelled (VBT RevB Sec. VIII-D: "Human claim labels for E4 cover at least the GATE responses of the local model and of the pilot-selected commercial model"). Replicate variance: per model and arm, as E1's, `awaiting_labels` for a cell whose subsample responses lack labels.
- **Inputs** (`load_design`): each pinned file's LF sha256 is reported to `on_read` (`verification_set`, `e4_responses`, `ratings`, kinds of the access log, 3.11) before any check; an unreadable one is `<kind>_unreadable` (exit 3), a sha256 mismatch `<kind>_sha256` (exit 6), a line that is not an object or not a response line `<kind>_invalid` (exit 3), a line outside the live items `<kind>_items` (exit 3), and an E4 line whose model is not in the verifier list `e4_responses_generator_unknown` (exit 3).
