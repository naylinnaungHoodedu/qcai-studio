SECTION 1 — WHAT THIS PRODUCT IS
================================================================================

QC+AI Studio is a full-stack learning platform for Quantum Computing + AI,
taught through the discipline of "hardware-constrained hybrid design" (NISQ
realism). It is a submission for the Handshake x OpenAI Codex Creator Challenge.

Learner-facing surface (live at qantumlearn.academy):
  - 11 modules / 12 lesson entry points (curriculum grounded in curated DOCX +
    MP4 source material).
  - Grounded search and Q&A with citations.
  - Teaching Assistant chat (page/lesson aware, RAG-grounded).
  - Lesson pages: video, key ideas, notes, formulas, source sections, quiz,
    flashcards.
  - Practice surfaces: Dashboard (learning analytics), Arena (real-time quiz
    game), Builder (drag-and-drop dependency game).
  - Simulations: 16 course studios + 18 academy labs (client-side models).
  - Projects: portfolio submissions + peer review.
  - Trust/ops surfaces: privacy, terms, accessibility, status, support,
    audit-fixtures, security.txt.

Access model: fully public curriculum (no login required); guest cookies enable
per-session dashboard/projects/builder/arena; Auth0 sign-in is optional.

NOTE on framing: this document treats the platform as a real product to be
hardened and simplified. The competition context is background, not the
organizing principle.

SECTION 2 — SYSTEM SNAPSHOT (ARCHITECTURE MAP)
================================================================================

2.1 FRONTEND  (apps/frontend)
-----------------------------
- Next.js 16.2.1 (App Router), React 19, TypeScript strict, TanStack Query
  (@tanstack/react-query). Utility: clsx. NO CSS framework and NO component
  library — styling is one hand-written stylesheet.
- Design system: a single monolithic file, apps/frontend/src/app/globals.css
  (~3,264 lines). ~10 CSS custom properties only. Self-hosted Space Grotesk font.
  DARK MODE ONLY.
- Rendering strategy (mixed):
    * ISR (revalidate 300s) for public content: /, /modules, /modules/[slug],
      /lessons/[slug], /syllabus, /quiz/[lessonSlug], /flashcards/[lessonSlug].
    * SSG (generateStaticParams) for simulation catalog: /simulations/[slug],
      /simulations/subjects/[subjectSlug](/[simulationSlug]).
    * SSR force-dynamic for private surfaces: /dashboard, /arena, /builder,
      /projects, /account, /search.
- Networking:
    * Same-origin reverse proxy: src/app/api/backend/[...path]/route.ts. All
      browser data calls go to relative /api/backend/... (satisfies CSP
      connect-src 'self'); the proxy forwards to the FastAPI backend, promotes
      the qcai_auth_token cookie to Authorization: Bearer, applies guest/CSRF
      headers, injects/strips demo-auth headers, streams bodies, applies
      per-path timeouts + one retry, returns structured 502/504 on failure.
    * Next-16 middleware: src/proxy.ts (Next 16 renamed middleware.ts ->
      proxy.ts). Mints a per-request CSP NONCE (x-nonce header, threaded to
      <body> in layout.tsx), builds the CSP, bootstraps guest sessions,
      re-asserts COOP/CORP.
    * EXCEPTION: ArenaPanel opens a DIRECT WebSocket to the backend origin
      (NEXT_PUBLIC_API_BASE_URL), NOT through /api/backend. This is the single
      break in the otherwise-clean same-origin pattern and is why CSP
      connect-src must include the API origin + wss://.
- Auth (hand-rolled, no SDK): Auth0 PKCE via src/app/auth/{login,callback,
  logout}/route.ts + src/lib/auth.ts; guest cookies via src/lib/guest-session.ts;
  demo-auth fallback (ENABLE_DEMO_AUTH, on in non-prod, off in prod).
- Security headers: split across TWO sources — static headers in next.config.ts,
  and the CSP + COOP/CORP (re)set per-request in src/proxy.ts. CSP relies on
  style-src-attr 'unsafe-inline' (inline style= attributes allowed app-wide).
- Tests: 19 integration suites under apps/frontend/tests (server-logic focused,
  tsx --test). Deepest is auth-and-proxy.integration.test.ts.

Key frontend files:
  src/app/page.tsx ............... home (hero, module cards, references, feature
                                   availability, dashboard/projects/sim links)
  src/app/modules/page.tsx ....... curriculum hub (stages, prerequisites, rubric)
  src/app/lessons/[slug]/page.tsx  lesson composition
  src/app/dashboard/page.tsx ..... private analytics (LearningDashboardView)
  src/components/primary-nav.tsx . responsive nav with <details> dropdown groups
  src/components/app-shell.tsx ... header + nav + footer + global assistant chat
  src/lib/navigation.ts .......... PRIMARY_NAV_ITEMS definition (8 groups)
  src/lib/api.ts ................. ~40 typed endpoint wrappers + cache modes
  src/lib/types.ts ............... all shared backend DTOs

2.2 BACKEND  (apps/api)
-----------------------
- FastAPI 0.128 + Uvicorn. SQLAlchemy 2.0 (Mapped/mapped_column). Pydantic v2 +
  pydantic-settings.
- DB: SQLite in dev (apps/api/qcai_dev.db), Postgres + Cloud SQL in prod
  (psycopg / pg8000 + cloud-sql-python-connector). Alembic 1.17 is PRESENT
  (one migration) but BYPASSED at runtime — schema comes from
  Base.metadata.create_all + a hand-rolled run_schema_upgrades() (core/
  schema_upgrades.py) that ALTERs in project_submissions.is_deleted and creates
  six composite indexes.
- 13 routers mounted in app/main.py: auth, content, assets, search, qa,
  assistant, analytics, admin, arena, builder, insights, projects, support.
- Middleware (executes: CORS -> security-headers(nonce CSP) -> request-id ->
  guest/CSRF protection -> routers). SlowAPI rate limiting on auth/qa/assistant/
  search/support/web-vitals.
- 15 tables (app/db_models.py), NO ORM relationships declared — joins are done
  manually in Python. Tables: user_accounts, user_sessions, notes,
  quiz_attempts, qa_interactions, analytics_events, public_web_vitals,
  support_requests, arena_profiles, arena_match_records, builder_runs,
  builder_shares, learner_profiles, learning_pulses, project_submissions,
  peer_reviews.
- Auth precedence in core/auth.get_current_user: (1) Auth0 RS256 Bearer via
  JWKS, (2) local session cookie (PBKDF2, 240k iters, 30-day sessions),
  (3) demo headers (if enabled), (4) guest cookie, (5) 401. RBAC via
  require_role().
- CSRF/origin protection: core/request_protection.py as global middleware for
  unsafe methods; bearer + demo exempt; session/guest must present matching
  CSRF cookie+header AND trusted Origin/Referer.

2.3 CONTENT PIPELINE (the heart of the backend)
-----------------------------------------------
- Course is BLUEPRINT-DRIVEN, not fully data-driven:
  services/content_assembler.py MODULE_BLUEPRINTS is a ~780-line hardcoded list
  of modules/lessons with authored title/summary/key_ideas/flashcards/quiz plus
  section_refs, video_file, document_file.
- services/docx_parser.py reads allowlisted .docx (python-docx), splitting at
  Heading/Title styles into SectionRecords.
- CourseStore.build() matches each lesson's section_refs against parsed headings
  via SUBSTRING MATCHING (fragile — a heading rename in a source doc silently
  drops sections, falling back to authored chunks).
- Video chapters: transcripts/<stem>.json if present, else a hardcoded
  CURATED_VIDEO_CHAPTERS fallback (services/transcripts.py).
- Retrieval chunks: RecursiveCharacterTextSplitter(700/120). Lessons with no
  DOCX match synthesize chunks from authored blueprint text so retrieval is
  never empty.

2.4 RETRIEVAL / RAG (services/retrieval_engine.py, qa_engine.py,
    teaching_assistant.py)
----------------------------------------------------------------
- Lexical token-overlap search ALWAYS on (pure Python, no external deps).
- Semantic backend (Pinecone + OpenAI embeddings) OPT-IN — enabled only when
  OpenAI key + embedding model + Pinecone key + index are all set. Fused with
  lexical via Reciprocal Rank Fusion (RRF_K=60, semantic weight 1.35).
- Retrieval mode reported to client via X-Retrieval-Mode header / retrieval_mode
  field: "lexical" | "lexical-fallback" | "hybrid-pinecone".
- Q&A (/qa/ask): OpenAI ChatOpenAI when key set, else a deterministic templated
  fallback ("local-grounded-fallback"). Persisted to qa_interactions.
- Teaching Assistant (/assistant/chat): Vertex AI Gemini preferred (raw httpx),
  else local grounded fallback. Page/lesson aware.

2.5 INFRA / DEPLOYMENT
----------------------
- Dockerfiles for api + frontend; root docker-compose.yml; infra/k8s manifests;
  Cloud Run production (ENABLE_DEMO_AUTH=false). Frontend output: standalone.
- Background workers (app/workers/): heartbeat loops, NOT a task queue —
  ingestion (rebuild course store, 300s), rag (refresh Pinecone, 180s),
  analytics (counts, 240s), seed_demo (one-shot). common.run_worker handles
  SIGTERM/SIGINT.

2.6 SPEC-vs-AS-BUILT GAP (worth remembering)
--------------------------------------------
The blueprint/spec (02_..., 03_...) envisioned: PostgreSQL on Cloud SQL,
Pinecone semantic retrieval, Auth0 with instructor/admin RBAC + review
workflows, GKE Autopilot, real video transcripts, instructor content-authoring
UI. The as-built MVP runs: SQLite by default, LEXICAL retrieval by default
(Pinecone only if keys present), hand-rolled auth with demo/guest fallback,
CURATED (not transcribed) video chapters, and a fully hardcoded curriculum with
NO instructor-authoring UI. "AI feedback"/"coach feedback" are keyword
heuristics, not LLM calls. This gap is not a defect list — it is the honest
delta between vision and MVP, and it frames where "software update" effort goes.

SECTION 3 — CURRENT-STATE UX AUDIT (per surface)
================================================================================

Cross-cutting problems (apply to most surfaces):
  X1. Navigation overload. 8 primary nav items: Overview, About, Modules,
      Projects, Practice[Dashboard,Arena,Builder], Simulations, Account, Search
      (src/lib/navigation.ts, rendered by src/components/primary-nav.tsx). No
      clear hierarchy between "learn" and "practice/meta".
  X2. Jargon-first. NISQ / VQA / QUBO / "qubit-budget" appear before any plain-
      language framing. Assumes graduate-level baseline even on "Beginner"
      labels.
  X3. Dark-only, heavy visual system. globals.css: --canvas #050915,
      --accent #1bd4ff (cyan), --accent-deep #7a6cff (purple), glassmorphism
      (backdrop-filter blur), a fixed body::before grid overlay + multiple
      stacked radial gradients. Striking, but noisy; contrast of --muted
      (#95acd1) on dark surfaces is borderline for WCAG AA on small text.
  X4. No design-token scale. Spacing/radius/type sizes are ad-hoc literals
      throughout the 3,264-line file (radii 14/16/18/20/22/24/28px; gaps
      10/12/14/16/18/20/28px). Hard to keep consistent or theme.
  X5. Responsiveness is present but unrefined. The stylesheet DOES define
      breakpoints at 1100 / 980 / 720 / 640px (verified in globals.css), so this
      is not a first build — remaining work is refinement: larger touch targets,
      denser-grid tuning, flashcard swipe, portrait arena timer. [Imp D10]

SECTION 4 — DESIGN PRINCIPLES FOR THE "ULTIMATE" VERSION
================================================================================

These principles govern every item in Section 5. Keep them stable.

P-1. ONE PRIMARY ACTION PER SCREEN. Every page has exactly one visually dominant
     CTA. Everything else is secondary/tertiary. Home leads with a single
     "Start learning" path.

P-2. PROGRESSIVE DISCLOSURE OF JARGON. Lead with plain language; make the
     technical term the second layer. Provide an inline glossary/term-hover
     ("NISQ = today's noisy, small quantum hardware"). A "Plain language" default
     with an optional "Show technical detail" toggle.

P-3. REAL DESIGN-TOKEN SYSTEM. Replace ad-hoc literals with a token layer:
     --space-1..8, --radius-sm/md/lg/pill, --text-xs..2xl, semantic color
     tokens (--bg, --surface, --text, --text-muted, --border, --accent,
     --success, --danger). This is the prerequisite for theming and consistency.

P-4. LIGHT + DARK THEMING. Add a light theme and honor prefers-color-scheme,
     with a persisted manual toggle (data-theme on <html>). [Imp D6] Ensure the
     nonce-CSP still allows the theme mechanism (no inline <style> blocks needed;
     use tokens).

P-5. ACCESSIBILITY AS A GATE. WCAG AA contrast for all text (re-check --muted on
     dark surfaces), full keyboard operation (arena 1-4, builder placement),
     visible focus (already present), and prefers-reduced-motion to disable the
     grid overlay / gradient animation / shimmer.

P-6. MOBILE-FIRST. Add a genuine small-phone breakpoint (~640px), larger touch
     targets, swipe for flashcards, portrait-friendly arena timer. [Imp D10]

P-7. CALM VISUALS. Dial back simultaneous gradients + fixed grid overlay; make
     the "quantum" aesthetic an accent, not a constant. Reserve motion for
     meaning.

P-8. HONEST LABELS. Where the UI says "AI feedback"/"mastery"/"readiness" but the
     value is a heuristic, either soften the copy or add a "how this is
     calculated" affordance. Trust is the product's core promise.
