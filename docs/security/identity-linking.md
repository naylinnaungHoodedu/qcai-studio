# Phase 8 identity linking

A verified principal binds to a random learner subject through a provider-scoped digest. The guest signing key can rotate independently. New bindings require identity to be enabled. An existing binding continues to address the same learner record after flag rollback. Legacy credentials and ordinary activity remain attached to the principal. Erasure serializes writers and verifies both keys and their dependent rows.

The guest claim requires a durable principal, a verified guest token, its matching CSRF proof, and a trusted origin. The claim rejects revoked, previously claimed, and known public guest identifiers. The transfer, one-shot revocation tombstone, and audit row share a transaction. The audit has keyed digests and table counts. The revocation tombstone uses a domain-separated digest whose recognition survives key rotation and feature rollback.

The merge takes per-skill mastery maxima, unions completions, takes componentwise attempt and clock maxima, and keeps the winning cursor or preference. Where a unique record such as a public handle collides, the pre-existing account row wins. Duplicate operation keys retain the account's receipt while the materialized record joins both sides.

The claim emits `subject.claimed` with the transferred-row count or `subject.claim_refused` for a denied claim. Review the structured security logs for outcomes and the linking audit table for the claim time, keyed digests, and table counts. The receipt audit keeps a receipt identifier, canonical receipt hash, table-set hash, and deleted total. Both audit tables expire 365 days after creation in every privacy mode. These audit rows outlive learner erasure within that period.

Claim uses `guest_legacy_upgrade_rate_limit` (5/hour by default), and self-service erasure confirmation uses `auth_login_rate_limit` (10/minute by default). A request that exceeds either limit receives 429. Consent reads and updates, export, and self-service erasure require a verified local session, signed guest credential, or Auth0 token with a nonblank string `sub`. An absent or blank Auth0 subject returns 401 with `LEARNER_IDENTITY` on or off. Inherited routes retain their identity-off credential behavior. The privacy routes refuse demo identities with 403. While Phase 8 is active, the shared authentication resolver also refuses demo aliases that identify an existing account, guest, learner subject, or recognized federated principal. Self-service erasure requires a trusted origin. The existing local-account deletion route requires a local session and password. With privacy enabled, both erasure routes verify zero remaining rows and commit the canonical receipt audit with the deletion.

Local accounts and guests lose their credentials on erasure. A retained federated principal can begin a fresh learner record on a later request that observes the current erasure epoch. The authentication session locks before row-locking selects and ORM or SQLAlchemy DML writes, including when a route updates only legacy learner tables. Arena writes lock their verified participants. The locked path refuses observations from earlier epochs even after a retained principal resumes activity. Both guard states age from `last_used_at` and expire after 365 inactive days in every privacy mode.
